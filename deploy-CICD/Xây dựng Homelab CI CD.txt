7. Deploy lần đầu và kiểm tra logs.

Kết quả mong muốn: Có một Next.js app truy cập được qua domain HTTPS, kết nối PostgreSQL và không mất dữ liệu sau khi restart container.

8. Giai đoạn 6 — Hoàn chỉnh CI/CD tự động

Dự kiến: Ngày 6

Đây sẽ là thành phần quan trọng nhất của homelab nếu bạn thường xuyên code và deploy dự án.

Pipeline đề xuất

1. Git Push

Bạn push code lên branch main

2. Continuous Integration

GitHub Actions chạy lint, test

3. Build & Publish

Build Docker image, đẩy lên GHCR

4. Private Deployment Trigger

GitHub runner kết nối Tailscale, gọi Dokploy API

5. Continuous Deployment

Dokploy pull image mới, cập nhật ứng dụng

6. Health Check

Kiểm tra API, website và kết quả deploy

Cách GitHub Actions triển khai vào Dokploy riêng tư

Nếu chỉ dùng GitHub-hosted runner và giữ Dokploy private thì runner không thể tự gọi một API chỉ truy cập được trong LAN.

Mình chọn giải pháp dùng Tailscale GitHub Action. Mỗi lần deploy, runner tạm thời tham gia tailnet, gọi Dokploy API rồi rời mạng sau khi hoàn tất. Tailscale hỗ trợ chính workflow này, với ephemeral runner và quyền truy cập giới hạn bằng tag/ACL. 
Tailscale Docs
+1

Ví dụ workflow cho một ứng dụng Node.js đã có Dockerfile:

YAML

name: CI/CD

on:
  push:
    branches: [main]

permissions:
  contents: read
  packages: write

concurrency:
  group: production-deployment
  cancel-in-progress: false

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Test
        run: |
          npm ci
          npm run lint --if-present
          npm run test --if-present

      - name: Define image name
        id: image
        shell: bash
        run: |
          echo "name=ghcr.io/${GITHUB_REPOSITORY,,}" \
            >> "$GITHUB_OUTPUT"

      - name: Login to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build and push
        uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: |
            ${{ steps.image.outputs.name }}:latest
            ${{ steps.image.outputs.name }}:sha-${{ github.sha }}

      - name: Connect to private server
        uses: tailscale/github-action@v4
        with:
          oauth-client-id: ${{ secrets.TS_OAUTH_CLIENT_ID }}
          oauth-secret: ${{ secrets.TS_OAUTH_SECRET }}
          tags: tag:ci

      - name: Trigger Dokploy deployment
        env:
          DOKPLOY_URL: ${{ secrets.DOKPLOY_URL }}
          DOKPLOY_API_KEY: ${{ secrets.DOKPLOY_API_KEY }}
          DOKPLOY_APP_ID: ${{ secrets.DOKPLOY_APP_ID }}
        run: |
          curl --fail-with-body -sS -X POST \
            "$DOKPLOY_URL/api/application.deploy" \
            -H "x-api-key: $DOKPLOY_API_KEY" \
            -H "Content-Type: application/json" \
            --data "{\"applicationId\":\"$DOKPLOY_APP_ID\"}"


Đây là template cho bước triển khai, chưa phải workflow có thể chạy nguyên xi nếu chưa cấu hình GHCR, Tailscale OAuth, ACL, các GitHub Secrets và Application ID trong Dokploy. DOKPLOY_URL phải là địa chỉ mà runner kết nối được qua Tailscale, ví dụ http://100.x.y.z:3000.

Trong Dokploy, có thể cấu hình image sử dụng tag latest để dễ bắt đầu. Pipeline đồng thời publish tag theo commit SHA để có thể truy xuất phiên bản cũ và phục vụ rollback rõ ràng hơn.

Với ứng dụng khác Node.js, thay bước test bằng lệnh tương ứng. Khi hệ thống hoàn thiện hơn, mình sẽ chuyển sang deploy image theo digest hoặc SHA cố định thay vì phụ thuộc vào latest.

Quy tắc cho CI/CD

- Chỉ deploy production sau khi CI thành công trên main.
- Không deploy tự động các PR chưa được kiểm duyệt.
- GitHub-hosted runner build image; PC ở nhà chủ yếu pull và chạy image.
- Token chỉ có quyền tối thiểu và lưu trong GitHub Secrets.
- Tailscale runner chỉ nên được phép gọi endpoint cần thiết trên Home Server.
- Mỗi ứng dụng có health check và quy trình rollback.

9. Giai đoạn 7 — Backup và phục hồi

Dự kiến: Ngày 7

Đây là phần mình sẽ làm trước khi đưa dữ liệu cá nhân quan trọng lên server.

Dữ liệu  Tần suất dự kiến  Nơi lưu
PostgreSQL dumps  Mỗi ngày  HDD và off-site
Application volumes quan trọng  Mỗi ngày  HDD và off-site
Dokploy configuration  Mỗi tuần và trước khi update  Off-site
Server configuration  Sau mỗi thay đổi  Git repo private, không chứa secret
Tài liệu, file uploads  Mỗi ngày  HDD và off-site

Dokploy hỗ trợ backup cấu hình/DB hệ thống và các database được quản lý lên S3-compatible storage. 
Dokploy
+1

Mình sẽ dùng:

- Local backup: Cron script thực hiện backup ra HDD, kiểm tra ổ đã mount trước khi ghi.
- Off-site backup: S3-compatible storage hoặc ổ ngoài tách khỏi PC.
- Restore test: Ít nhất mỗi tháng kiểm tra khôi phục một database vào môi trường thử nghiệm.

HDD nằm trong cùng PC không phải bản backup độc lập. Nếu nguồn điện, mainboard hoặc sự cố khác làm hỏng cả hai ổ, bạn có thể mất toàn bộ dữ liệu. GitHub cũng không thay thế backup database và file uploads.

Mục tiêu ban đầu: dữ liệu backup cách nhau tối đa khoảng 24 giờ, và phải có quy trình khôi phục đã kiểm tra thực tế.

12. Quản lý tài nguyên cho RAM 8 GB

Phần này rất quan trọng, vì không thể đối xử chiếc PC như một VPS có 32–64 GB RAM.

RAM budget dự kiến khi chạy tải nhẹ

Ubuntu + Docker

0.6–1.2 GB

Dokploy và thành phần nội bộ

0.7–1.5 GB

PostgreSQL cho dự án

0.3–0.8 GB

1–2 ứng dụng web/API

0.6–1.5 GB

n8n + monitoring + Homepage

0.5–1.2 GB

Dự phòng cho cache, spikes

1.5–2.5 GB

Các mức này là ngân sách ước tính để lập kế hoạch, không phải số liệu benchmark hay cam kết sử dụng RAM. Mức thực tế phụ thuộc từng app và workload.

Với cấu hình này, mình đặt một số giới hạn:

- Chỉ 1 replica cho mỗi web service.
- Không chạy build nặng trực tiếp trên máy khi đã có CI trên GitHub.
- Giới hạn memory cho container khi phù hợp; không đặt giới hạn quá thấp khiến dịch vụ liên tục OOM.
- Tạm dừng ứng dụng không dùng thường xuyên.
- Không cài GitLab, Elasticsearch, Prometheus stack đầy đủ và Kubernetes production ngay.
- Giữ dung lượng SSD trống ít nhất khoảng 20% nếu có thể, theo dõi Docker image và log growth.

Khi cần nâng cấp, 16 GB RAM là ưu tiên số một.

15. Kết quả cuối cùng mình muốn đạt được

Home Server v1.0 — Definition of Done

Push code lên GitHub là có quy trình CI/CD tự động deploy dự án.
Có thể deploy nhiều ứng dụng Next.js, Node.js, Go hoặc Python với domain riêng.
Có PostgreSQL persistence, backup và restore đã được thử nghiệm.
Có giao diện quản trị, dashboard, monitoring và cảnh báo.
Có thể quản lý server từ xa qua Tailscale, không public SSH hay database.
n8n chạy được các automation cá nhân mà không cần Redis.

Chi phí bắt buộc để bắt đầu có thể gần như bằng 0 nếu tận dụng toàn bộ phần cứng cũ và các free tier phù hợp. Tuy nhiên, vẫn cần tính điện, mạng, domain nếu dùng domain riêng, và chi phí lưu trữ backup ngoài máy.

Bước tiếp theo

Mình khuyên bắt đầu với Ngày 1: kiểm tra HDD, kiểm tra USB Wi-Fi trên Ubuntu Live và chuẩn bị USB cài hệ điều hành. Đây là các bước chưa xóa dữ liệu và giúp xác định chính xác khả năng triển khai trên PC của bạn.

Còn một điểm chưa xác nhận: PC sẽ kết nối bằng dây LAN hay bắt buộc dùng USB Wi-Fi. Kế hoạch trên hỗ trợ cả hai, nhưng mình sẽ ưu tiên kiểm thử driver Wi-Fi trước nếu bạn không thể cắm LAN.
